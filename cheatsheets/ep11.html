The BookMyShow API, production-ready · ▶ 1:21:46

The 5 steps, for this episode

  1. Requirements 3 min · Browse cities → cinemas → shows. Survive launch-day load and crashes. Know one server’s limit.
  2. Estimates 4 min · Load-test one server first (k6). requests ≈ VUs × s means the test is the limit. Servers = peak ÷ one server, + 1 spare (general).
  3. HLD 8 min · Client → Nginx (LB, HTTPS, gzip, rate limit) → app servers with PM2 × cores → MongoDB; Prometheus + Grafana watching.
  4. Deep dive 8 min · Request layers. Feature-based modules. Docker. The 512-connection limit and keep-alive.
  5. Trade-offs 5 min · Cores help only when CPU-bound. gzip: bytes vs CPU. Docker costs laptop speed. Engineering, not over-engineering.

Make AI safe first · ▶ 27:05

Run nothing without OK · no git add/commit/push · no DB deletes · no file deletes · stay in the folder · no code before the plan is approved.

Rules are requests; hooks are locks. Hooks run in every mode (exit 2 blocks); “ask” is skipped in auto mode. Test them from a second session.

4 places, 4 jobs · ▶ 47:00

bootstrap/what starts at boot: DB, logger, CORS, Helmet, Swagger
integrations/outside services: SMS, WhatsApp, email, payment
modules/features: cities/ = route, schema, service, repository, types
shared/small helpers · config/env.ts loads env once

Say it like this

  • “Before scaling, I load-test one instance and check the test isn’t the bottleneck: if requests ≈ VUs × seconds, the script is sleeping.”
  • “Node uses one core, so I run PM2 in cluster mode, a worker per core; it also restarts crashed workers.”
  • “Nginx sits in front as a reverse proxy: one public port, HTTPS and gzip at the edge, the app port stays private.”
  • “Each feature module has its own route, schema, service and repository; only the repository touches the DB.”

🚩 Red flags: don’t say or do

  • Trusting a load-test number without reading the script (sleep, think time).
  • Adding cores when the bottleneck is somewhere else.
  • Plain node in production with nothing to restart it.
  • Exposing the app port instead of a reverse proxy in front.
  • Load-testing through Nginx with the default 512 connections.
  • An AI agent with push, DB deletes or network and only “ask first” rules.
  • Redis and Elasticsearch in bootstrap on day one (over-engineering).
