The 5 steps, for this episode

  1. Requirements 3 min · Any language, script or typo; meaning (“मच्छर खा गए”); only my dark store’s stock; ms answers; admin adds products.
  2. Estimates 4 min · vectors = products × 1,024 × 4 B (general); tag time = products × 0.074 s (100 in 7.4 s).
  3. HLD 8 min · Admin → API (202) → Kafka → AI worker → Mongo + Typesense + Redis. Search: Redis → query vector → Typesense hybrid.
  4. Deep dive 8 min · Tags vs vectors, hybrid rank, pincode → store filter, DLQ, night batch, guard at 5 places.
  5. Trade-offs 5 min · Local model (no per-call cost, your RAM) vs paid API. Typesense (RAM) vs Elasticsearch (heavy). AI suggests, human approves.

Guardrails · ▶ 22:34 · 29:11 · 30:42

AI only generates; it never touches the DB. Missed searches: no auto-add; the AI suggests a match, the admin approves with one click (one wrong tag spoils every search). Bad words are checked at 5 places (suggest, admin tags, Kafka worker, missed searches, trending); fail closed if Ollama is down; a veg product never gets a non-veg word.

Say it like this

  • “I generate multilingual tags once, when the product is added, so the model is off the shopper’s path.”
  • “Tags catch exact words and typos; vectors catch meaning. Typesense ranks both together.”
  • “Saving a product returns 202; a Kafka worker tags, embeds and writes Mongo, Typesense and Redis.”
  • “Every search carries the dark store id, so results are only what that store can deliver.”

🚩 Red flags: don’t say or do

  • A wildcard LIKE on the DB as “search”.
  • Calling the LLM on every keystroke or search.
  • Auto-adding zero-result queries as tags.
  • Letting the model write to the DB.
  • One India-wide index for a 10-minute delivery app.
  • Elasticsearch on day one “because everyone uses it”.
