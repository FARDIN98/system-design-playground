The method, and the demo it was run on · ▶ 07:07 · 41:21 · 44:22

The 5 steps: “walk me through a backend you didn’t write”

  1. Requirements 3 min · Purpose in one line; users (shopper, admin); core value (search in any language from the nearby store).
  2. Estimates 4 min · 31 APIs (13 public, 4 rate-limited, 14 admin); RAM index = products × KB each (general).
  3. HLD 8 min · Fastify API → Kafka → workers → MongoDB (truth), Redis (cache), Typesense (search), Ollama (AI).
  4. Deep dive 8 min · Add product (202 → ingest → enrich → index, DLQ) and search, with file:line for each step.
  5. Trade-offs 5 min · Typesense (RAM, fast) vs Elasticsearch (disk, heavy); local Ollama vs paid AI; shared admin key vs JWT.

Two AIs · ▶ 22:17 · 46:56

Coding AI (Claude Code, Cursor, Copilot in Ask mode) for questions about this code. Free chat AI (Meta AI, ChatGPT, DeepSeek, Gemini) for new terms: saves tokens. Limit hit? Same rules, another tool. Don’t know the stack? “I’m a Java developer”: Java parallel first, then file:line. Web chat can’t see a folder: npx repomix or gitingest.

Say it like this

  • “I set the AI’s rules first: read-only, file:line for every claim, facts and assumptions apart.”
  • “Adding a product returns 202; three Kafka workers save, enrich and index it.”
  • “Search reads Typesense directly and never waits on the LLM; analytics go to Kafka after the reply.”
  • “Typesense is fast because the index is in RAM; at crores of products I’d test splitting or Elasticsearch.”

🚩 Red flags: don’t say or do

  • Prompt and pray: copy, paste, push.
  • Trusting a claim without its file:line.
  • Letting the AI run installs or migrations.
  • Asking everything in one message.
  • Asking a free chat AI about your repo.
  • Picking an engine without a POC.
